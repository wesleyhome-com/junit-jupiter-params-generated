GeneratedParametersTest

@Target(allowedTargets = [AnnotationTarget.FUNCTION])
@API(status = API.Status.STABLE, since = "3.0")
@TestTemplate
@ExtendWith(value = [GeneratedParametersTestExtension::class])
annotation class GeneratedParametersTest(val name: String = DEFAULT_DISPLAY_NAME, val filters: Array<String> = [], val strategy: GenerationStrategy = GenerationStrategy.CARTESIAN)

Marks a test whose parameters are generated, running it once per combination of generated values.

A method named <test>_filter filters that test without being listed anywhere, so invalid combinations are never generated rather than generated and skipped. Use <test>_filter_<name> for several rules, and filters to share a rule between tests. A filter takes only the parameters it is about, matched by name, and must be static or in a companion object because filtering happens before the test instance exists.

strategy = PAIRWISE covers every pair of parameters with every pair of their values instead of the whole product, and takes the pairs to cover from the combinations the filters accept. See GenerationStrategy.

Worked versions of both, compiled and checked by the annotation processor, are examples.Filtering and examples.Pairwise in the examples module; the README shows them in full.

A parameter typed as a Kotlin value class takes its values from any source for the type it wraps, so @LongSource([0, 1]) amount: Money runs with Money(0) and Money(1). Each value goes through the class's constructor; one its init rejects fails the invocation that would have received it, naming the parameter, the value and the reason. Filters declare the value class itself. See examples.ValueClasses.

val filters: Array<String>

Names of methods that decide which generated combinations run. Each is matched by parameter name to the generated parameters it declares, so a rule names only what it is about, and a combination runs only if every filter accepts it.

name
Link copied to clipboard
val name: String

the display name given to each invocation. Supports the same placeholders as @ParameterizedTest: {index} for the 1-based invocation number, {arguments} for the generated values, {argumentsWithNames} for name=value pairs, {displayName} for the test method's own display name, and {0}, {1} and so on for a single generated value by position. Only generated parameters are listed; parameters resolved by other extensions are not.
